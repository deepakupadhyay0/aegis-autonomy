# Logging

The `logging::logging` library provides bounded process-local asynchronous
logging. An executable enables it by injecting
`logging::node_logging_adapter_c` through `base_core::base_node_options_s`.
`base_core` depends only on the logging interface and remains usable without
the concrete logging package.

The calling thread formats only fixed-capacity metadata and attempts a
non-blocking push into the process queue. A single `SCHED_OTHER`, low-priority
writer thread owns file rotation, optional console output, and optional
diagnostic DDS publication. There is no logging service, socket transport, or
second asynchronous queue.

Logging configuration is generated from
`autonomy_config/config/logging.toml.default` and may be overridden by
`AEGIS_AUTONOMY_CONFIG_DIR/logging.toml`. Configuration is loaded and
validated once during logger initialization.

Each logger initialization records the CMake project, ROS package version,
Git repository name, local and CI commit identifiers, branch, UTC build time,
and repository `VERSION_STR`. The repository version is maintained centrally
in `common/version.h`; Git and build fields are generated by CMake and require
no runtime Git access.

`AEGIS_AUTONOMY_LOG_DIR` takes precedence over the configured `log_directory`.
When the environment variable is absent, a relative TOML directory is resolved
against `AEGIS_AUTONOMY_CONFIG_DIR`; that directory defaults to the process
working directory. The resolved absolute log directory is printed to
`std::cerr`. Each node uses a deterministic file name.

`file_size_bytes` controls the rotation threshold. `max_files` includes the
active file, so the default value of three retains the active file and two
archives. `standalone_mode` is reserved for a future separate-process backend
and currently has no runtime effect.

The fixed-capacity queue never overwrites an existing record and never blocks a
producer. A producer immediately rejects its incoming record when the queue is
full or contended and increments the corresponding atomic counter. Reaching
90% capacity signals the writer to flush without moving sink work onto the
producer.

A low-priority diagnostic thread reports queue capacity, current and peak
utilization, accepted and processed records, full and contention drops,
pressure events, flushes, sink failures, and an `increase`/`monitor`/`ok`
buffer recommendation. It
submits its fixed-size report through the same non-blocking queue and never
accesses a sink directly. Queue diagnostics are enabled by default with a
five-second interval.

`enable_console_log` and `enable_diagnostic_dds` are disabled by default.
Queue diagnostics and their interval are enabled and configured through TOML.
All sink work remains on the writer thread.
